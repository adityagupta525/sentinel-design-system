## The capability, first — and it is built

The ask was to make the agent expert at Figma before designing anything. What that turned into:

- **Figma's own skills are already installed and the MCP is connected** as *Centricity Wealth Tech
  Pvt Ltd*, Full seat on the org. `figma-use` (the Plugin API) and `figma-generate-library` (the
  phased codebase→library workflow, v2.0.2) are the engine. Nothing better exists on the internet —
  the third-party repos found are snapshots of these same skills.
- **A house skill, `sentinel-figma`, sits on top of them** — which is exactly what Figma's own
  guidance says a design-system skill should do rather than duplicate. It carries Sentinel's truth:
  the generated token map, the component inventory, the naming, the four gotchas, and what cannot
  be 100%.
- **A parity gate**, because "it matches" is otherwise an opinion. `npm run check:figma-parity`
  proves the probe can fail before anyone trusts a pass; on real screens it returns 0.00% for a
  matching pair and 99.48% + FAIL for a mismatched one.

## Five decisions already taken from the repository, not from a template

1. **One mode, named `Value`.** Sentinel has no dark mode. A Light/Dark pair would invent 28 colour
   roles nobody has designed.
2. **Palette hidden (`scopes = []`), roles exposed.** 31 literals underneath, 28 roles on top.
3. **14 text styles, not font-size variables.** A designer picks `body`, never 14px.
4. **One page per group, not per component.** 98 pages is unnavigable; the 11 groups are already
   the system's taxonomy.
5. **No Smart Animate.** The system has one easing, six durations and explicitly no shared-element
   transition.

sitting — Figma's own skill says 20–100+ writes per phase and it is right.

## What cannot be 100%, said before starting rather than after

- **`DotField` and the splash's dot phase** are `<canvas>`, computed per frame. One settled frame as
  a component, plus an exported video beside it, with the page saying the motion lives in code.
- **Live motion.** Six durations and one easing are documented in Foundations. A Figma prototype
  illustrates the timing; it is not the timing.
- **Sub-pixel text layout.** The browser and Figma break lines at very slightly different widths.
  Parity is measured at the component box, not at the glyph — hence the 2% threshold.

Everything else — colour, spacing, radius, the type ramp, shadow, structure, every component and
every screen — is reproducible exactly. **Both fonts are Google Fonts** (Urbanist 400/500/600/700,
Darker Grotesque 500) and load natively in Figma, so type fidelity is achievable rather than
approximated. That was the one thing that could have made "100%" impossible, and it is not a
problem.

## Running it

```bash
npm run build:figma-map      # regenerate the token map and inventory from the repository
npm run check:figma-parity   # prove the parity probe can still fail
```

`build:figma-map` belongs in the same commit as any token change, the same way `check:integrity`
and `build:scale` do. A Figma file built from a stale map disagrees with the product, and nothing
in Figma will tell you.
