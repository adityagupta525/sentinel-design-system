# Sentinel in Figma

Figma's own skills are the engine. **`figma-use` is how you talk to the Plugin API and
`figma-generate-library` is the phased workflow for building a library from a codebase** — load them,
follow them, do not re-implement them. Figma's own guidance on writing a design-system skill says it
should sit *on top of* those, not duplicate them, and this one does.

What this skill adds is the part those cannot know: **Sentinel's truth**, generated from the
repository, plus the four things that will actually go wrong here.

## The one rule

**Every number in the Figma file comes from `references/figma-tokens.json`, not from a screenshot,
not from memory, and not from the generic defaults in the Figma skill.**

That file and the two markdown maps beside it are regenerated by `npm run build:figma-map` from
`design-system/tokens/*.css` and the components themselves. A token list typed into a skill drifts
the first time a token changes and the drift is invisible until someone measures a screen. This one
cannot drift, for the same reason `sentinel-craft/references/scale.md` cannot.

## Before anything

1. **`references/tokens.md`** — every variable, text style and effect style, with the exact CSS token
   each answers to, and **scopes measured** from the properties that actually consume the token
   across 153 files. Also names what is deliberately *not* a variable, and why.
2. **`references/inventory.md`** — 98 components in 11 groups, with the props from each `.d.ts`, and
   the rule for turning a prop into a variant / TEXT / BOOLEAN / INSTANCE_SWAP property.
3. **`references/parity.md`** — how a Figma component is *proven* to match the rendered one. A claim
   of fidelity that was not measured is not a claim.
4. **`references/benchmarks.md`** — what Blade, Material 3 and Apple's kit actually do, what was
   taken and what was rejected for this product.
5. **`sentinel-craft`** — `references/rules.md` (the four hard rules) and `references/scale.md`.
   Everything settled there stays settled in Figma. Figma is a second rendering of this system, not
   a second chance to design it.

## Five things already decided — do not re-open them in Figma

| Decision | Why, and what breaks if the Figma default is used instead |
| --- | --- |
| **One mode, named `Value`** | Sentinel has no dark mode: `grep prefers-color-scheme design-system/tokens/*.css` returns nothing. A Light/Dark pair invents a surface the product does not have, and every variable gets a second value nobody set. |
| **Palette hidden, roles exposed** | 31 literal colours are `Palette` with `scopes = []`; 28 aliases are `Colour` and are what a designer picks. A designer reaching for `bronze` instead of the role is how identity starts leaking into colour, which rule 1 forbids. |
| **14 text styles, not font-size variables** | A type role is a composite (`weight size/leading family`). The role is the unit a designer picks — `body`, never 14px. The four primitives exist underneath and are bound by the style. |
| **One page per group, not per component** | 98 pages is a file nobody can navigate. The 11 groups are already this system's taxonomy. Split a group only when one component's variant matrix needs the room. |
| **No shared-element transition** | The system has one easing and six durations and explicitly has none. Smart Animate between two frames of the same card invents motion the product does not ship. |

## Build order

Follow `figma-generate-library`'s phases. These are the Sentinel-specific contents of each.

**Phase 0 · Discovery.** Read the three generated references. Call `get_libraries` on the target
file. Print the gap analysis. **Lock the scope before a single write** — and this file's scope is
already measured: 137 variables, 14 text styles, 9 effect styles, 98 components, 11 group pages.

**Phase 1 · Foundations.** Six collections, one mode each: `Palette` · `Colour` · `Type` ·
`Layout` · `Radius` · `Stroke`. Every variable gets its measured scopes and
`setVariableCodeSyntax('WEB', 'var(--the-exact-css-token)')` — that string is in the JSON, use it
verbatim so Dev Mode hands an engineer the token this repository actually has. Then the 14 text
styles and 9 effect styles. The two gradients and the two auras are **paint styles**, not variables.

**Phase 2 · File structure.** Cover → Getting started → Foundations → `---` → the 11 group pages →
`---` → Screens → Utilities. Foundations renders the palette, the type ramp, the spacing tiers and
the motion table — the same four things `sentinel-craft/references/scale.md` states, so the file
teaches the scale rather than assuming it.

**Phase 3 · Components, one at a time, atoms first.** `shell` and `text` before `chat` and `cards`;
`icons` as a set delivered whole. Every fill, stroke, gap, radius and text style **bound to a
variable** — a hardcoded value in a component is the Figma equivalent of the adherence lint, and the
ceiling here is zero, not 61. Prove each one with `references/parity.md` before starting the next.

**Phase 4 · Screens, then QA.** `figma-generate-design` builds the screens from the components.
Every screen is 375×812. Then Code Connect, the naming audit, and the unresolved-bindings audit.

## Naming

Slash-separated, derived mechanically from the CSS token by dropping `--` and replacing `-` with `/`
at the first segment. The JSON carries the exact string for every one; do not re-derive it by hand.

```
--color-bronze        → color/bronze          var(--color-bronze)
--space-16            → space/16              var(--space-16)
--h-row-2l            → h/row-2l              var(--h-row-2l)
--radius-16           → radius/16             var(--radius-16)
--type-body-font      → text style "body"     (binds four variables)
```

Components keep their source names exactly — `SentinelBlock`, not `Sentinel Block`. The `.jsx`, the
`.d.ts`, the spec page and the Figma component must all say the same word, or Code Connect has
nothing to match on.

## The four gotchas

These are the ones that will actually cost a day.

1. **`DotField` is a `<canvas>`.** Its dots are computed per frame from arc-length-even sampling of
   the mascot outline. There is no vector to import and no honest way to reproduce it as layers.
   Ship **one settled frame** as a component and a short exported video beside it, and say in the
   page documentation that the motion lives in code. Do not hand-place dots.

2. **11.5px, 42px and 0.5px are real.** `--text-11-5` is the one non-integer step and it earned the
   slot; `--h-row` is 42; `--border-hairline` is 0.5. Figma takes all three. Anyone "tidying" them to
   12 / 44 / 1 has restyled the product — see `sentinel-craft`, and the standing rule: never restyle.

3. **Both fonts are Google Fonts and load natively.** Urbanist (400/500/600/700) and Darker
   Grotesque (500). Nothing has to be uploaded, so type fidelity is achievable rather than
   approximated — but check the weights are actually present in the file before building a text
   style, because a missing weight silently falls back and the whole ramp looks a half-step light.

4. **Sentinel has no blur and no images.** If a Figma layer acquires a background blur or a raster
   fill, it did not come from this system. The one exception is the canvas paper texture, which is a
   3px radial-gradient pattern and is an image fill in Figma by necessity.

## What cannot be 100%, stated up front

Say this before building, not after someone measures it.

- **Canvas rendering** — `DotField`, and the splash's dot phase. Static frame plus video.
- **Live motion** — Figma prototypes approximate the six durations and the one easing. Every
  duration and curve is documented in Foundations; the prototype is an illustration of the timing,
  not the timing itself.
- **Sub-pixel text layout** — the browser and Figma break lines at very slightly different widths.
  Parity is measured at the component box, not at the glyph.

Everything else — colour, spacing, radius, type ramp, shadow, structure, every component and every
screen — is reproducible exactly, and `references/parity.md` is how that gets proven rather than
claimed.

## Changing something

`npm run build:figma-map` after any token change, in the same commit, the same way
`check:integrity` and `build:scale` are run. A Figma file built from a stale map is a file that
disagrees with the product, and nothing in Figma will tell you.
